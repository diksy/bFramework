# Arsitektur BikininFramework (mode hybrid)

Rekomendasi mode: **hybrid** (sudah disetujui, lihat `APPROVED.md`); salvage per file di `salvage.md`.

## 1. Stack final
PHP 8.1+ (`declare(strict_types=1)`, PSR-12, PHPStan 8) · tanpa Composer di server, autoload PSR-4 buatan sendiri · PDO MySQL 8/MariaDB 10.6/SQLite 3 · Apache/LiteSpeed `.htaccess` · vanilla JS tanpa build · PHPUnit di dev/CI (PHP 8.1–8.5) · library JWT di-vendor (`app/core/vendor/`, hanya dimuat M15) · ekstensi: daftar di `rules.md` (+ GD untuk gambar upload), `curl` opsional.

## 2. Struktur `src/`
```
src/public_html/{index.php,.htaccess,assets/{app.css,sidebar.js,builder.js,upload.js,install-canary.js},_pc/}  ← _pc = cache halaman (M16)
src/app/.htaccess (deny-all, ARCH-02) · bootstrap.php (satu-satunya perakit) · cli/{update,admin-reset,compile}.php (cek PHP_SAPI)
src/app/core/{Contracts,Core,Runtime,Auth,Upload,Cache,Install,Builder,Sso,Update,vendor}/  ← namespace bFramework\<Folder>
src/app/{definitions/{models,pages},extensions,config/config.example.php,storage/{cache,sessions,logs,ratelimit,uploads,sso}}
src/tests/{Arch,Core,Runtime,Auth,Upload,Install,Builder,Integration,Fixtures}/  ← tidak masuk zip
tools/{build-release.php,sign-update.php}  ← di akar repo (bukan src/), tidak masuk zip
```
Letak nyata: `Core/` = M1, M2, M4, M5, M6, `FileSessionStore`, `Csrf`, `TransportPolicy`, `SkipMiddleware`; `Runtime/` = M3, `Authorizer`, `CurrentIdentity`, M8, M9, `HomeRedirect`; `Auth/` = M10, M11, `StepUp`; `Upload/` = M12; `Cache/` = M16; `Install/` = M13; `Builder/` = M14 (+ `AuditLog` tabel hanya milik Builder); `Sso/` = M15; `Update/` = M17.
Lapisan (ARCH-03, `tests/Arch/LayerDependencyTest::LAYERS`, aktual): Contracts(0), Core(1), Runtime(2), Auth(3), Upload(3), Cache(3), Install(4), Builder(4), Sso(4), Update(4). Lapisan bawah tak pernah `use` lapisan atas, **tanpa pengecualian**; lapisan setara (Auth/Upload/Cache; Install/Builder/Sso/Update) juga tidak saling `use` (Sso boleh `use` Auth karena lebih rendah); folder di `core/` yang tak terdaftar di `LAYERS` (kecuali `vendor`) = tes gagal. Lapisan bawah memanggil atas hanya lewat interface/closure yang dirakit `bootstrap.php`. Setiap file PHP di `app/` diawali `defined('APP_BOOTED') || exit;`.

**M12b Integrasi upload** (kontrak baru):
- *Definisi*: field file = `{"type":"string","upload":{"mimes":[…],"maxBytes":int}}` (FieldType tetap, ARCH-04). `DefinitionSchema` memvalidasi `upload` lewat aturan `UploadPolicy` (duplikasi aturan di Runtime, tanpa `use Upload`), memaksa kolom `string(32)`, menolak `unique`/`default`/`min`/`max`, field file sebagai `owner`, dan sort/filter/aggregate atas field file. Kolom tabel model berisi **fid saja** (nullable bila tidak `required`).
- *Interface* `Runtime\FileRefs` (stub dulu): `meta(string $fid): ?array{owner_id:?int, model:?string, ref_id:?int, mime:string, size:int}`; `claim(string $fid, int $userId, string $model, int $refId): bool` (UPDATE bersyarat `fid=? AND owner_id=? AND model null` → true bila 1 baris); `release(string $fid): void`; `deleteForRef(string $model, int $refId): int`. Diimplementasikan `UploadService`.
- *Validator*: nilai = string `ID_RE` atau null/`''` (→ null); selain itu error.
- *ModelRepository* (param baru `?FileRefs $files`; null + nilai file non-null = tolak, fail-closed): `fileErrors()` setelah Validator — wajib login; `meta` ada, `owner_id === userId`, belum ter-attach (atau sama dengan nilai baris saat ini → dilewati), mime ∈ `upload.mimes`, size ≤ `maxBytes`; semua kegagalan = satu pesan generik (tanpa oracle). Create: insert → `claim` tiap file sebelum hook after*; claim gagal → hapus baris + error validasi. Update: field tidak dikirim = tetap; fid baru di-`claim`, fid lama di-`release` setelah update sukses. Delete: setelah baris terhapus → `deleteForRef(model, id)`; kegagalan dicatat, tidak membatalkan.
- *Endpoint* `POST /files` (di `FileController::upload`): multipart `file`, `model`, `field`, `_csrf` (CSRF aktif, 419); anonim → 403; `can(def, Create) || can(def, Update)` (termasuk `requireAmr`), field harus field file → selain itu 404; policy diambil dari definisi ter-compile, **tidak pernah** dari klien; `store(..., ownerId=userId)` tanpa model/ref; respons JSON 201 `{id, mime, size, name}`, error JSON dengan status `UploadRejected`. Alur **dua langkah** (upload → fid di hidden input → submit form); multipart langsung di form PageController tidak didukung v1. `assets/upload.js` (nonce CSP) mengisi hidden input; form menampilkan tautan `/files/{id}` untuk nilai saat ini.
- *Kuota/rate*: `store()` dengan ownerId null ditolak kecuali flag internal; rate limit `upload:<uid>`; cek kuota + insert metadata di bawah `flock` per owner (`storage/uploads/.lock/<uid>`) agar atomik; `MAX_PIXELS` turun ke 12 juta; `deleteForRef` loop sampai habis (bukan 1000); `purgeOrphans(maxAge=86400)` hapus file belum ter-attach, dijadwalkan 1/200 via `Deferred`.
- *Perakitan* `bootstrap.php`: `buildUploads(appDir, Connection, Definitions, CurrentIdentity, ?Logger): array{UploadService, FileController}`; dir = `upload.dir` atau `app/storage/uploads`; `docroot` diisi kecuali mode cadangan; opsi `upload.{maxFilesPerOwner,maxBytesPerOwner,rateMax,rateWindow}`; `configureRuntime()` meneruskan `FileRefs` ke `PageController::configure`; `index.php` memanggil `registerRoutes`.
- *File disentuh*: `Runtime/{FileRefs(baru),DefinitionSchema,Validator,ModelRepository,PageController,ComponentRenderer,Format}.php` + view form, `Upload/{UploadService,FileController}.php`, `bootstrap.php`, `public_html/index.php`, `assets/upload.js`, `tests/Arch/LayerDependencyTest.php`, `docs/api-ekstensi.md`.
- *Tes wajib*: SEC-FILE-01 (tanpa sesi/tanpa hak baris → 404 identik; berhak → 200 + nosniff + sandbox; dir di docroot ditolak) · SEC-FILE-02 (PHP ber-`.jpg`, SVG di definisi ditolak compile, mime di luar policy field, ukuran > maxBytes 413) · SEC-FILE-03 IDOR: fid milik user lain / sudah ter-attach / claim paralel kedua → gagal generik · SEC-FILE-04 endpoint: tanpa CSRF 419, anonim 403, tanpa hak model 403, field bukan file 404, rate 429, kuota 413 · SEC-FILE-05 siklus: hapus baris → metadata + fisik hilang (>1000 file), ganti file → lama terhapus, update tanpa field → tetap, orphan dibersihkan · ARCH-03 Upload terdaftar, Runtime tak `use Upload`.

**M13 Installer** (`Install/`, lapisan 4): `Installer(appDir, docroot, Clock)::isInstalled(): bool` (`storage/installed.lock` ada), `checks(): list<Check{id; ok; msg}>` (PHP ≥8.1, ekstensi, storage writable, layout normal/cadangan, `app/` di luar docroot), `install(InstallInput): InstallResult{resetUrl}` · `InstallInput` readonly (`appUrl`, `allowedHosts` (default host dari `appUrl`), `db*`, `mail*`, `adminEmail`, `adminName`, `registration=false`; password `#[\SensitiveParameter]`, tidak pernah ditampilkan ulang) · `InstallController::registerRoutes` (`GET|POST /install`, CSRF aktif, rate limit).

Kunci pendahuluan: `storage/install_token_<hex16>` (nama acak, isi acak, 0600) dibuat saat kunjungan pertama dan wajib dimasukkan (`InstallInput::installToken`, di luar kontrak awal; nama/isi tak pernah ditampilkan, pemilik membaca lewat file manager/FTP). `ensureGuard()` (penjaga `.htaccess` deny-all, mode cadangan) wajib lolos **sebelum** token dibuat.
- *Kanari* (S1, kontrol salah-konfigurasi, keputusan pemilik): di mode cadangan installer menulis `storage/canary_<hex>.txt`; `assets/install-canary.js` meng-fetch dari browser (harus 403/404, redirect tidak dianggap lulus) lalu `POST /install/canary` (CSRF, rate limit kunci terpisah dari POST /install) menyimpan `canary.proven`; instal diblokir sampai terbukti. Laporan klien dipercaya (bukan pertahanan terhadap penyerang aktif); layout normal direkomendasikan.
- *Langkah* (gagal di tengah = tidak menulis lock): uji koneksi DB → tulis `config/config.php` atomik (tmp+rename, **0600**, `var_export`) berisi `APP_URL`, `APP_ENV=production`, `APP_KEY=base64_encode(random_bytes(48))`, `APP_HOST`, `ALLOWED_HOSTS`, `MAIL_FROM`, `SMTP_*`, `DB_*`, `auth.*`, `upload.*` → skema: `AuthSchema::install`, `FilesTable` (Migrator `planCreate`, idempoten), tabel `migrations` (versi skema core, untuk M17) → admin: `AccountStore::create(email, name, null, 'pending')` + peran `admin`, `OneTimeToken::issue(RESET, 3600)`; tautan ditampilkan sekali di layar (+ email bila SMTP OK). **Tanpa password default.** Tautan kedaluwarsa (1 jam) → `php app/cli/admin-reset.php <email>` (CLI saja, ada sejak INT-F5; `/auth/forgot` hanya untuk akun aktif; menolak `APP_URL` http di produksi).
- *Kunci*: tulis `installed.lock`, hapus `install_token_*` dan kanari; sesudahnya `/install` → 404 dan tidak bisa dijalankan ulang tanpa menghapus lock + config secara manual.
- *Tutup fail-open HostGuard* (review M10): bila `APP_URL` terisi tapi `ALLOWED_HOSTS` kosong, `index.php` memakai host dari `APP_URL`; `AuthKit::middleware` hanya melewati HostGuard bila `devMode` **dan** daftar kosong; mode belum terinstal tetap memasang `SecurityHeaders` dan tidak pernah membangun tautan dari `Host`.

**Tambahan hardening (SEC-3..5, INT-F1/F4/F5; di luar kontrak awal, berlaku)**:
- *Bootstrap*: `ensureCompiled(appDir, Connection, ?Logger): bool` — satu flock eksklusif `storage/first_build.lock` (urutan kunci first_build → build), compile + buat tabel model **create-only**, penanda `cache/.schema_ok` (berisi versi) ditulis terakhir; "table already exists" = sukses. `app/cli/compile.php [--dry-run] [--apply-migrations [--allow-loss]]`: build atomik + tabel baru; ubah skema tabel ada hanya dengan flag eksplisit; exit 0/1/2.
- *M10/M11*: `Auth\StepUp` (`/auth/step-up`, jendela 900 dtk, `next` ter-whitelist) menjaga `/admin/*`: lolos bila amr `sso`, atau `pwd` (+`otp` bila ber-TOTP), atau step-up ≤15 mnt · `Core\TransportPolicy::configure(appUrl, TRUSTED_PROXIES)` (APP_URL https → cookie Secure/`__Host-`; `X-Forwarded-Proto` nilai terakhir, hanya dari proxy tepercaya) · `Runtime\HomeRedirect` (rute `/`: halaman pertama yang boleh diakses / login) · `Response::file` (di luar kontrak M1) · `UserStore` delete/list/count.
- *Log*: `RotatingFileLogger(dir, maxBytes, keep, file, maxPerMinute|null, …)`; dua instance (`app.log` dibatasi laju, `audit.log` terpisah untuk audit admin, tidak pernah dipotong) berbagi `.lock`; flag re-entrancy static per `realpath` dir; `recoverAfterFatal()` untuk handler shutdown; kegagalan rotasi audit → satu baris ke `app.log` + `.audit.log.skip`. Tabel `audit_log` hanya milik Builder.

## 5. Threat model ringkas
Aset: sesi & cookie, hash password, token (ingat saya, reset, refresh SSO), `APP_KEY`/`client_secret`/kredensial DB/SMTP, data model, file upload, definisi JSON, file core.
Aktor: anonim, user login (peran berbeda), akun hosting tetangga, developer (tepercaya), penyerang jaringan, server SSO palsu.
| Modul | Ancaman utama | Mitigasi |
| --- | --- | --- |
| M1/M2 | Akses langsung `app/`, CSRF, brute force, Host poisoning | ARCH-01/02, SEC-PER-*, HostGuard fail-closed, tautan dari `APP_URL` |
| M3/M9 | SQL injection, mass assignment, IDOR, hook palsu | allowlist, binding, guarded, `constrain()`+`forceOwner()`, HookRunner verifikasi ulang |
| M4/M5 | XSS, bocor stack trace/rahasia | auto-escape, CSP nonce, halaman generik, Redactor |
| M7 | Session fixation/hijack, sesi dibaca tetangga | storage sendiri, regenerate, HttpOnly/Secure/`__Host-` |
| M10/M11 | Credential stuffing, enumerasi, pra-registrasi, token dicuri, eskalasi peran, admin terakhir hilang | Argon2id, throttle, pesan+waktu seragam, akun pending tanpa password, token hash sekali pakai ≤60 mnt, regenerate, `RuleViolation` |
| M12/M12b | Webshell/polyglot/SVG, IDOR fid, file orang lain di-attach, banjir upload | luar docroot, finfo+GD, policy dari definisi, `claim` bersyarat owner, 404 seragam, rate+kuota ber-flock |
| M13 | Instalasi didahului orang lain, token/sqlite terunduh (AllowOverride None), installer aktif terus, password default, rahasia di zip | `install_token_<hex>` acak, kanari + `ensureGuard`, `installed.lock`, admin pending + tautan reset, config 0600, zip tanpa config/storage (risiko sisa: laporan kanari klien palsu) |
| M14/M17 | Builder terekspos, path traversal, paket palsu | BuilderGate 404, realpath, Ed25519 + manifest, `UpdatePaths` whitelist, kunci placeholder fail-closed |
| M15 | Token palsu, CSRF login, replay logout, takeover via email, amplifikasi fetch IdP | RS256 saja, PKCE+state+nonce, `jti`, tautan via `sub` + bukti password, TTL min 60 dtk + rate limit back-channel |
| M10/M16 | Cookie ingat-saya dicuri membuka admin, halaman terlarang tersaji dari cache | StepUp 15 mnt, requireAmr; purge gagal = rollback + karantina `_pc` |
